## 1. MCP 解决什么问题

AI 编程最大的限制之一是：它默认不知道你的真实工程环境。

它不知道：

- 项目文件在哪里
- 接口文档是什么
- 组件库怎么用
- 数据库结构如何
- 设计稿长什么样
- 当前构建是否通过
- 测试结果是否正常

MCP 的价值可以理解为：

> 让 AI 通过标准化方式连接外部工具和上下文。

也就是说，AI 不只是聊天，而是可以读取、查询、调用真实工具。

## 2. 可以怎样理解 MCP

可以把 MCP 想象成 AI 和外部世界之间的插座。

AI 本身是大脑，但它需要工具：

- 读文件
- 查接口
- 查文档
- 搜代码
- 跑测试
- 访问数据库
- 调用内部平台
- 获取设计稿信息

MCP 提供一种统一方式，让这些工具可以被 AI 使用。

## 3. 没有 MCP 时的问题

没有工具接入时，AI 常见问题是：

- 只能根据你粘贴的片段判断
- 无法主动查找项目里的相似代码
- 不知道组件库真实 API
- 不知道接口返回结构
- 无法执行测试和构建
- 容易编造不存在的文件、函数和字段

这也是为什么 AI 经常"看起来很自信，但实际不对"。

## 4. 有 MCP 后的理想流程

以新增一个后台页面为例。

没有 MCP 时，你要手动告诉 AI：

- 目录结构
- 相似页面代码
- 接口文档
- 组件库用法
- 代码规范

有 MCP 后，理想情况是 AI 可以：

1. 搜索项目中相似页面
2. 读取组件库文档
3. 查询接口定义
4. 查看项目规范
5. 生成代码
6. 执行 TypeScript 检查
7. 执行 Lint
8. 根据错误自动修复

这就是从"AI 聊天助手"到"AI 工程助手"的变化。

## 5. 前端常见 MCP 场景

### 5.1 代码仓库 MCP

让 AI 能搜索和读取项目代码。

用途：

- 查找相似页面
- 理解目录结构
- 定位 bug
- 分析组件依赖
- 辅助重构

### 5.2 组件库文档 MCP

让 AI 能查询组件文档和示例。

用途：

- 正确调用组件
- 生成符合规范的页面
- 避免编造组件 API
- 帮助写组件文档

### 5.3 接口文档 MCP

让 AI 查询后端接口信息。

用途：

- 生成 API 封装
- 推导 TypeScript 类型
- 实现页面联调
- 校验字段映射

### 5.4 设计稿 MCP

让 AI 读取设计信息。

用途：

- 识别页面结构
- 生成基础布局
- 提取颜色、间距、字体
- 辅助还原 UI

### 5.5 测试和构建 MCP

让 AI 能执行验证命令。

用途：

- 跑单测
- 跑类型检查
- 跑 Lint
- 跑构建
- 根据错误修复代码

## 6. MCP 和上下文工程的关系

MCP 不是替代上下文工程，而是增强上下文工程。

上下文工程关注：

> AI 应该知道什么。

MCP 关注：

> AI 如何获得这些信息，如何调用这些工具。

没有上下文设计，MCP 也可能变成"工具很多，但 AI 不知道该用哪个"。

所以 MCP 最好和 Rules、Skill 配合使用。

例如在 Skill 中规定：

```md
执行 CRUD 页面任务时：

1. 先通过代码搜索工具查找相似页面
2. 再通过接口文档工具查询接口定义
3. 再通过组件库文档工具确认组件用法
4. 编码后通过构建工具检查结果
```

## 7. MCP 不是万能的

MCP 能让 AI 接入工具，但不能自动保证结果正确。

你仍然需要：

- 明确任务目标
- 提供业务背景
- 限制修改范围
- 设计执行流程
- Review 代码结果
- 设置质量门禁

MCP 解决的是"AI 获取信息和执行工具"的问题，不解决"人类是否清楚自己要什么"的问题。

## 8. 个人前端如何低成本理解 MCP

如果你现在不是在搭企业级 AI 平台，可以先从思维上理解：

> 以后有价值的知识和工具，最好能被 AI 调用。

你可以先沉淀这些内容：

- 项目上下文文档
- 组件库文档
- 接口说明
- 常用命令说明
- 页面模板
- AI Rules
- 常用 Skill

即使暂时没有 MCP，这些内容也能提升 AI 编程质量。

## 9. 小结

MCP 的核心价值是：

> 让 AI 能连接真实工程环境，而不是只靠聊天窗口里的片段工作。

对前端来说，MCP 最重要的方向是：

```txt
代码仓库
组件库文档
接口文档
设计稿
测试构建工具
内部研发平台
```

当这些都能被 AI 使用时，前端基建就从"人使用的工具体系"升级成了"人和 AI 共同使用的工程体系"。

## 1. 为什么生成页面也需要流程

很多人让 AI 生成页面时，会直接输入：

```txt
帮我写一个用户管理页面。
```

结果往往不稳定。

有时候能跑，有时候接口瞎编，有时候组件乱用，有时候风格和项目完全不一致。

问题不在于"AI 不能生成页面"，而在于缺少工程化流程。

一个真实项目里的页面不是孤立代码，它依赖：

- 业务需求
- 路由结构
- 接口定义
- 组件库
- 权限体系
- 状态管理
- 样式规范
- 错误处理
- 质量检查

所以 AI 生成页面也要有流程。

## 2. 推荐流程总览

可以把 AI 生成页面拆成 8 步：

```txt
1. 明确需求
2. 收集上下文
3. 查找相似页面
4. 设计实现方案
5. 生成代码
6. 自查和修复
7. 人工 Review
8. 沉淀模板和经验
```

不要让 AI 一步到位。越复杂的任务，越要分阶段。

## 3. 第一步：明确需求

需求至少要包含：

- 页面名称
- 页面入口
- 核心功能
- 字段信息
- 接口信息
- 交互要求
- 权限要求
- 验收标准

例如：

```md
新增用户管理页面。

功能：
- 查询用户列表
- 新增用户
- 编辑用户
- 删除用户
- 启用 / 禁用用户

字段：
- 姓名
- 手机号
- 角色
- 状态
- 创建时间

验收：
- 支持分页
- 支持 loading
- 删除前二次确认
- 接口错误要提示
```

## 4. 第二步：收集上下文

要让 AI 生成符合项目的代码，需要准备：

- 项目技术栈
- 目录结构
- 组件库规则
- 接口封装规则
- 相似页面
- 代码风格
- 修改边界

可以把这些写在任务说明里，也可以让 AI 先读取相关文件。

## 5. 第三步：查找相似页面

这是非常关键的一步。

页面生成最好的参考不是通用教程，而是你项目里已经存在的相似页面。

例如：

```txt
请先阅读 src/pages/role/index.vue。
总结它的：
1. 搜索表单写法
2. 表格写法
3. 弹窗写法
4. 接口调用方式
5. 分页和 loading 处理
```

让 AI 先学习项目已有模式，再生成新页面。

## 6. 第四步：先出方案，不要直接改

推荐先让 AI 输出方案：

```txt
先不要修改代码。
请根据需求和参考页面，输出实现方案：
1. 需要新增或修改哪些文件
2. 每个文件的职责
3. 页面数据流
4. 组件使用方式
5. 可能的风险点
```

你确认方案后再让它编码。

这样可以避免 AI 直接大范围乱改。

## 7. 第五步：生成代码

生成代码时要给出明确边界：

```txt
现在开始实现。
只允许修改：
- src/pages/user/index.vue
- src/api/user.ts

禁止修改：
- src/components
- src/router
- src/styles

要求：
- 使用 BaseTable
- 使用 BaseDialog
- 使用 BaseForm
- 保持和 role 页面一致的风格
```

AI 生成时，要尽量让它在既有工程模式里工作。

## 8. 第六步：补齐页面状态

很多 AI 生成页面只关注"主流程"，容易漏掉状态处理。

你要明确要求：

- loading 状态
- empty 状态
- error 状态
- 删除二次确认
- 表单校验
- 提交中禁用按钮
- 请求失败提示
- 分页重置
- 弹窗关闭后清理状态

这些细节决定页面是否能进入真实业务。

## 9. 第七步：让 AI 自查

生成后不要直接结束，让 AI 自查。

可以要求：

```txt
请检查你刚才生成的代码：
1. 是否有 TypeScript 类型问题
2. 是否有未定义变量
3. 是否有未使用变量
4. 是否符合项目组件使用规范
5. 是否存在重复逻辑
6. 是否有可能的异常状态没有处理
```

如果工具支持执行命令，还可以让 AI 跑：

```bash
pnpm typecheck
pnpm lint
pnpm build
```

## 10. 第八步：人工 Review

AI 自查不能替代人工 Review。

人应该重点看：

- 需求是否满足
- 业务逻辑是否正确
- 接口字段是否映射正确
- 是否破坏已有代码
- 是否引入过度封装
- 是否有安全和权限问题
- 用户体验是否完整

AI 适合生成初稿，人负责架构判断和最终把关。

## 11. 第九步：沉淀模板

做完一个页面后，不要马上结束。

可以沉淀：

- 这类页面的 Prompt 模板
- 页面生成 Skill
- 组件使用规则
- 常见坑
- Review Checklist
- 可复用代码片段

例如沉淀成：

```txt
Skill：新增管理后台 CRUD 页面
```

下次再做类似页面，效率会更高。

## 12. 一个完整 Prompt 示例

```txt
你是一个熟悉本项目的前端工程师。

任务：新增用户管理页面。

请按以下流程执行：
1. 先阅读 src/pages/role/index.vue，理解项目中后台列表页的写法。
2. 再阅读 src/api/role.ts，理解接口封装方式。
3. 先输出实现方案，不要直接改代码。
4. 我确认后再开始实现。

页面要求：
- 支持用户列表查询
- 支持新增、编辑、删除
- 支持分页
- 支持 loading 和错误提示
- 删除前需要二次确认

组件要求：
- 表格使用 BaseTable
- 弹窗使用 BaseDialog
- 表单使用 BaseForm

限制：
- 不允许修改公共组件
- 不允许修改全局样式
- 不允许直接使用 axios
```

## 13. 小结

AI 生成页面的关键不是"让它一次写完"，而是把页面开发拆成可控流程。

推荐记住：

```txt
先理解
再计划
再编码
再自查
再 Review
再沉淀
```

当你能把这套流程稳定下来，AI 就不再只是临时帮手，而会变成前端研发流程中的一部分。

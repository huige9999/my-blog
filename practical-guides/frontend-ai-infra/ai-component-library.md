## 1. 为什么组件库要适配 AI

过去组件库主要服务人类开发者。

开发者阅读文档，理解 API，然后手写代码。

AI 时代，组件库还要服务 AI。

如果组件文档清晰、示例完整、约束明确，AI 就能更准确地生成符合项目规范的组件调用代码。

反过来，如果组件文档混乱，AI 很容易：

- 编造不存在的 props
- 错用事件
- 忽略插槽
- 混淆基础组件和业务组件
- 生成不符合团队规范的代码

所以组件库建设需要考虑"AI 可读性"。

## 2. 什么是 AI 友好的组件文档

AI 友好的组件文档应该具备：

- 用途清晰
- API 明确
- 示例丰富
- 场景分类
- 反例说明
- 约束明确
- 命名稳定
- 类型完整

人类可以根据经验补全语义，但 AI 更依赖显式说明。

## 3. 组件文档应该怎么写

一个组件文档可以包含这些部分。

```md
# UserSelect 用户选择器

## 用途

用于选择系统用户，支持单选、多选、远程搜索和禁用指定用户。

## 适用场景

- 表单中选择负责人
- 分配任务处理人
- 设置审批人

## 不适用场景

- 不适合用于选择部门
- 不适合用于选择外部客户

## 基础用法

<UserSelect v-model="userId" />

## 多选

<UserSelect v-model="userIds" multiple />

## Props

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| modelValue | number \| number[] | - | 选中的用户 ID |
| multiple | boolean | false | 是否多选 |
| disabledUserIds | number[] | [] | 禁用的用户 ID |

## Events

| 事件 | 说明 |
| --- | --- |
| change | 选择变化时触发 |

## 注意事项

- 多选时 v-model 必须是数组
- 不要直接传用户对象，统一传用户 ID
```

这种结构既适合人读，也适合 AI 解析。

## 4. 示例比 API 更重要

AI 很擅长模仿示例。

所以组件文档不能只有 API 表格，还要有典型示例。

例如：

- 基础用法
- 表单中使用
- 弹窗中使用
- 和接口联动
- 禁用状态
- 错误示例

示例越贴近真实业务，AI 生成代码越稳。

## 5. 反例也很重要

组件文档里可以明确写"不推荐写法"。

例如：

```md
## 不推荐

不要这样写：

<UserSelect :value="user" />

原因：
UserSelect 只接收用户 ID，不接收完整用户对象。
```

反例能减少 AI 误用组件。

## 6. 组件 API 设计要稳定

AI 生成代码依赖组件 API。如果 API 经常变化，AI 上下文很容易过期。

因此组件库 API 要尽量：

- 保持命名稳定
- 避免同义参数
- 避免过多魔法行为
- 保持类型清晰
- 有明确废弃策略

例如不要同时存在：

```txt
userId
value
modelValue
selectedUser
```

命名混乱会让人和 AI 都困惑。

## 7. 从组件库到代码生成

当组件库文档足够规范后，就可以让 AI 生成页面代码。

例如：

```txt
请使用组件库中的 BaseTable、BaseForm、BaseDialog 实现用户管理页面。
组件用法参考以下文档。
不要使用原生 table 和 form。
```

如果 AI 能读取组件文档，它就可以更准确地生成：

- 表格列配置
- 表单项配置
- 弹窗结构
- 查询条件
- 操作按钮
- 校验规则

这就是组件库和 AI 编程结合的价值。

## 8. 组件库可以沉淀成物料

组件不一定只以代码形式存在，也可以沉淀成物料。

例如：

- 查询表单物料
- 列表页物料
- 弹窗表单物料
- 详情卡片物料
- 权限按钮物料
- 上传区域物料

这些物料可以成为 AI 生成页面时的模板。

AI 不一定从零开始写，而是组合已有物料。

## 9. AI 可以辅助组件库建设

AI 不只是使用组件库，也可以帮助维护组件库。

例如：

- 根据源码生成组件文档
- 根据 API 表格生成示例
- 检查文档和源码是否一致
- 生成单元测试
- 分析组件 API 是否复杂
- 辅助重构旧组件
- 生成迁移指南

但这些都需要人工 Review，尤其是涉及公共组件变更时。

## 10. 组件库文档的 AI 化改造清单

可以用这个清单检查你的组件文档：

- 是否说明组件用途
- 是否说明适用和不适用场景
- 是否有基础示例
- 是否有业务场景示例
- 是否有 Props 表
- 是否有 Events 表
- 是否有 Slots 表
- 是否有 TypeScript 类型
- 是否有注意事项
- 是否有反例
- 是否有版本变更说明

## 11. 小结

AI 时代，组件库的价值会进一步放大。

传统组件库解决的是：

> 人如何复用代码。

AI 友好的组件库解决的是：

> 人和 AI 如何共同复用工程资产。

组件文档越清晰、示例越完整、约束越明确，AI 生成代码就越不容易跑偏。

组件库不再只是 UI 资产，而是 AI Coding 的重要上下文基础设施。

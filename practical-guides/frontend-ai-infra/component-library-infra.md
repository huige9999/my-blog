## 1. 组件库不是组件集合

很多人以为组件库就是把项目里常用的 Button、Input、Table、Modal 抽出来。

这只是第一层。

真正的组件库基建关注的是：

- 组件如何分层
- 组件 API 如何设计
- 样式和主题如何统一
- 文档和示例如何维护
- 组件如何测试
- 组件如何发布
- 组件如何服务多个项目
- 组件如何让 AI 正确调用

组件库不是"组件仓库"，而是一套前端研发资产体系。

## 2. 组件分层

一个成熟的组件体系通常可以分为几层。

### 2.1 基础组件

基础组件是最底层的通用 UI 能力，例如：

- Button
- Input
- Select
- Modal
- Table
- Form
- Tabs
- DatePicker

基础组件一般不直接包含业务逻辑，重点是稳定、通用、可组合。

### 2.2 业务组件

业务组件带有一定业务语义，例如：

- UserSelect
- DepartmentTree
- PermissionButton
- UploadAvatar
- AreaCascader

业务组件往往会依赖具体接口、权限规则或业务字段。

### 2.3 领域组件

领域组件比业务组件更进一步，代表某个业务领域的可复用能力，例如：

- 商品选择器
- 订单状态流转组件
- 审批流组件
- 组织架构选择器
- 数据权限配置器

领域组件通常不是单纯 UI，而是封装了领域知识。

### 2.4 页面模板

页面模板是更高层的复用，例如：

- 列表查询页
- 表单编辑页
- 详情页
- 管理后台 CRUD 页
- 审批配置页

页面模板特别适合和 AI 代码生成结合。

## 3. 组件 API 设计

组件库的核心之一是 API 设计。

好的 API 应该具备：

- 语义清晰
- 默认行为合理
- 可扩展
- 不暴露过多内部细节
- 保持稳定
- 易于被文档和 AI 理解

例如一个用户选择器：

```vue
<UserSelect
  v-model="userId"
  multiple
  clearable
  :disabled-user-ids="[1, 2, 3]"
  @change="handleUserChange"
/>
```

这个 API 比直接暴露内部请求逻辑更稳定。

## 4. 基础组件和业务组件的边界

一个常见问题是：到底什么该放进组件库？

可以用一个标准判断：

> 如果组件不依赖具体业务接口和业务规则，它更适合做基础组件。
> 如果组件带有业务语义和业务规则，它更适合做业务组件或领域组件。

比如 Table 是基础组件，而 UserTable 通常是业务组件。

## 5. Design Token 和主题系统

组件库不能只靠 CSS 随便写。要有统一的设计变量，例如：

- 颜色
- 字体
- 圆角
- 间距
- 阴影
- 层级
- 动效

这些变量可以抽象成 Design Token。

例如：

```css
:root {
  --color-primary: #1677ff;
  --radius-base: 6px;
  --spacing-md: 16px;
}
```

主题系统的价值在于：

- 统一视觉风格
- 支持换肤
- 支持多品牌
- 降低样式维护成本

## 6. 组件文档

组件文档不是可有可无的说明书，而是组件库的入口。

好的组件文档应该包含：

- 组件用途
- 基础示例
- 常见场景
- API 参数
- 事件说明
- 插槽说明
- 注意事项
- 反例
- 最佳实践

AI 时代，组件文档还有一个新价值：

> 它不仅给人看，也给 AI 读取。

如果文档写得清晰，AI 生成组件调用代码的质量会明显提升。

## 7. 组件测试

组件测试通常包括：

- 单元测试
- 交互测试
- 快照测试
- 视觉回归测试
- 类型测试

不是所有团队都要一步到位，但核心组件至少应该有基本测试。

组件库的稳定性会直接影响多个业务项目，一旦基础组件出问题，影响面非常大。

## 8. 发布与版本管理

组件库需要有清晰的版本策略：

- patch：修复问题
- minor：新增能力
- major：破坏性变更

同时要维护 changelog，让业务项目知道升级风险。

如果是 monorepo，可以用 pnpm workspace、changesets 等工具管理多个包。

## 9. 组件库和 AI 的关系

AI 时代，组件库要考虑"AI 可调用性"。

也就是说，组件文档和示例要足够清晰，让 AI 能知道：

- 什么时候用哪个组件
- 组件有哪些必填参数
- 常见组合方式是什么
- 哪些写法是不推荐的
- 组件和业务接口如何配合

未来高质量组件库不仅是给人用的，也是给 AI Agent 调用的工程资产。

## 10. 小结

组件库基建的目标不是"少写几个组件"，而是建设一套稳定的前端复用体系。

从低到高可以理解为：

```txt
基础组件
↓
业务组件
↓
领域组件
↓
页面模板
↓
物料体系
↓
AI 可调用的组件资产
```

当组件库能被人稳定使用，也能被 AI 准确理解和调用，它就从传统组件库升级成了 AI 时代的前端基建。

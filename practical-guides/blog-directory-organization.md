## 文章归档的决策依据

- 01_输入笔记：它是不是来自我正在看的东西？比如视频课、技术文章、开源项目、官方文档等
- 02_实战手册：它以后能不能当操作手册复用？比如 服务器部署、wsl2配置、博客站点搭建等
- 03_专题研究: 它是不是我对某个问题的理解框架？比如：并发调度器如何设计？前端工程化如何拆层
- 04_观点沉淀：我经常会思考的一些更抽象的问题，比如：AI时代程序员定位、大厂前端需要什么能力、同学的AI使用方法论是否跑偏


### 01_输入笔记

看教程、文章、项目时的提取记录。
把外部输入转成自己的理解，不追求完整体系。

举个例子:

```
01_输入笔记
├── 课程笔记
│   ├── 渡一大前端
│   ├── 架构课
│   └── AI工程化课程
├── 文章阅读
│   ├── React并发特性阅读.md
│   ├── Cursor文档阅读.md
│   └── MCP官方文档阅读.md
├── 项目阅读
│   ├── 若依前端架构阅读.md
│   ├── vben-admin阅读.md
│   └── 某开源项目源码阅读.md

```

这个目录不要要求太高，允许它"脏一点"。
它的价值是：**帮你把输入先接住，避免看完就忘。**

## 实战手册和专题研究的区别

- 实战手册：下次照着做
- 专题研究：想明白一个问题


## 一篇文章的状态流转机制

一篇文章是有可能拆分成3个状态的：

```
输入笔记 → 专题研究 / 实战手册 → 观点沉淀
```


举个例子：

我看了一节Vue transition的课，先写：

```
01_输入笔记/课程笔记/Vue transition 课程笔记.md
```

后来工作中遇到动画不生效，整理解决方案：

```
02_实战手册/工程搭建/Vue transition 动画不生效排查.md
```

最后想明白了 transition 和 animation 的本质区别：

```
03_专题研究/动画与交互/CSS transition 和 animation 的本质区别.md
```

再进一步，我总结出了:业务前端为什么需要理解浏览器渲染机制:

```
04_观点沉淀/职业发展/业务前端如何从问题修复走向原理能力.md
```


这样有个好处：我可以不需要在一开始就要求一篇文章是完美的

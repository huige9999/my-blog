## 我的痛点

我发现自己经常陷入一个困境：看别人的源码能看懂，但让我从零开始写一个类似的工具，脑子就一片空白。看了很多开源项目、刷了不少代码阅读题，但真正动手写的时候还是不知道从哪下手。

后来我意识到问题在于——我一直停留在"输入"层面，缺少一个**系统性的输出训练**。光看 50 个开源项目，不如自己从空白页推 10 个小工具。关键不是数量，而是每个工具都要经历完整的思考链路：

```
调用侧设计 → API 契约 → 流程口述 → 状态建模 → 最小实现 → 扩展能力
```

## 我的训练计划

我给自己定了一个量级：**8～12 个小工具，每个 2～4 轮迭代，持续 4～8 周**。重点不是赶进度，而是确保每个工具都真正从"调用侧"开始推演。

### 第一阶段：4 个核心模式

这一阶段的目标是建立最基本的"库级代码思维"。

#### 1. 队列 / 调度类

**我要练的**：并发任务调度器、请求队列、异步任务池

**核心模式**：入队 → 等待 → 条件满足 → 执行 → 完成后继续推进

**训练点**：队列思维、状态推进、异步流程、内部 run/schedule 驱动

#### 2. 事件系统类

**我要练的**：EventEmitter、发布订阅、mitt 简化版

**核心模式**：订阅事件 → 保存回调 → 触发事件 → 执行回调 → 取消订阅

**训练点**：API 契约、回调管理、映射关系、解绑机制

比如我会先从调用侧开始设计：

```js
const bus = new EventBus()

const off = bus.on('login', user => {
  console.log(user)
})

bus.emit('login', { name: 'vichel' })

off()
```

#### 3. 缓存 / 资源管理类

**我要练的**：LRU Cache、带过期时间的 Cache、请求缓存

**核心模式**：读缓存 → 命中返回 → 没命中则创建资源 → 容量满了则淘汰旧资源

**训练点**：数据结构选择、状态一致性、边界条件、get/set 语义

```js
const cache = new LRUCache(3)

cache.set('a', 1)
cache.get('a')
cache.set('b', 2)
```

#### 4. 状态机 / 控制器类

**我要练的**：Promise 状态机简化版、弹窗管理器、播放器状态机、请求状态管理器

**核心模式**：`idle → pending → success / error` 或 `closed → opening → opened → closing`

**训练点**：状态约束、状态转换、非法操作处理

```js
modal.open()
modal.close()
modal.toggle()
```

### 第二阶段：4 个前端常见抽象

第一阶段练顺手之后，我会继续练这几个：

1. **防抖 debounce / 节流 throttle** — 时间控制
2. **重试器 retry** — 失败恢复
3. **请求去重 dedupeRequest** — 资源复用
4. **中间件 compose** — 函数组合

其中 `compose` 尤其值得深入，理解了它就理解了 Koa、Redux、Axios 拦截器等框架的中间件模型。

### 第三阶段：2 个组合型项目

最后，我要把多个模式组合起来，做两个接近"库设计"的综合项目：

**RequestManager** — 并发控制 + 缓存 + 重试 + 超时 + 取消

**ModalManager** — 队列 + 优先级 + 互斥 + 生命周期事件

## 我的目标

训练结束的标志不是"我看懂了"，而是我能够做到以下几点：

1. **先写调用侧**，不急着写实现
2. 能说清每个 API 的契约
3. 能列出内部需要维护哪些状态
4. 能画出状态流转图
5. 能自己写出最小可用版本
6. 能说出每个扩展能力改的是代码的哪个部分

比如拿到一个并发调度器，我能直接说出：

- 优先级 → 改的是取任务策略
- 取消 → 改的是任务有效性判定
- 暂停 → 改的是是否继续取队列
- 重试 → 改的是失败后的流转逻辑
- 超时 → 改的是任务失败判定条件

达到这个程度，说明我真正掌握了这个模式，而不是在背代码。

最近在跟一门数据结构与算法的课，但我不想把它当成"体系化学习"来啃——那样太容易拖垮节奏。我的目标很明确：**不是为了成为算法选手，而是让自己在复杂前端业务、性能优化和高级前端面试中，有一个稳定的数据结构与算法底盘。**

这篇文章是我给自己整理的学习计划，也顺便梳理一下哪些内容值得深挖，哪些该果断跳过。

## 一、我的四个学习目标

学完之后，我希望自己能达到这几个结果：

### 1. 面试不卡壳

- 简单题稳定快速写出
- 中等题能识别类型并写出主体逻辑
- 能说清楚时间复杂度、空间复杂度
- 数组、字符串、树、栈、队列、哈希、递归、DP 基础题不被卡住

但不追求难题稳定 AC、竞赛算法熟练、手写红黑树——这些对高级前端来说投入产出比太低。

### 2. 能处理复杂前端数据结构

这其实比刷题更重要。日常业务里遇到的结构远比 LeetCode 复杂：

- 菜单树、路由树、权限树、组件树
- 表单 schema、AST、JSON 嵌套结构
- 列表分组聚合、缓存结构、LRU、Diff 思想

这些如果能熟练处理，直接就是项目竞争力。

### 3. 建立复杂度意识

看到一段代码，能快速判断 O(n)、O(nlogn)、O(n²)、O(logn)，以及是否存在重复遍历、能否用 Map 优化、能否缓存、有没有递归栈风险。

这个能力在做性能优化、大数据量列表、复杂表格、低代码、可视化配置平台时，判断力的差距会非常明显。

### 4. 沉淀知识卡片和最小 Demo

每个核心模块学完，我要产出一套东西：1 张技术卡片 + 2～5 道高频题 + 1 个前端场景 Demo。这样算法才能从"刷过的题"变成"带得走的能力"。

## 二、课程内容的优先级划分

我按自己的目标把课程内容分成了四档：

### A 类：必须重点学

这些是高级前端的主线内容：

| 章节 | 为什么重要 |
|------|-----------|
| 02. 前置知识 | 复杂度、递归、数据结构基础 |
| 03. 数组、二分、归并、快速排序 | 高频面试 + 性能基础 |
| 03. 链表、栈、队列、双端队列 | 高频题型，栈和队列尤其重要 |
| 04. 集合、字典 | Map / Set 思维，前端数据处理核心 |
| 04. 二叉树 | 树结构处理能力，前端非常重要 |
| 04. 堆与堆排序 | Top K、优先队列、任务调度基础 |
| 04. 图中的 DFS / BFS、LRU | 前端场景价值很高 |
| 05. DP 基础 | 面试底线，不能完全不会 |
| 05. 回溯基础 | 组合、子集、路径类问题 |
| 05. 贪心基础 | 高频题够用即可 |

### B 类：认真听，不必深挖

理解就行，不需要大量练习：顺序查找、冒泡排序、选择排序、插入排序、折半插入排序、希尔排序、循环队列、双链表、循环链表、二叉搜索树、图的邻接矩阵/邻接表。

### C 类：浅尝辄止

投入产出比不高：插值查找、平衡二叉树单旋/双旋、哈夫曼树、最小生成树、分发糖果、摆动序列、图高级问题。

### D 类：可以跳过

双向循环链表细节、AVL 旋转细节、哈夫曼树完整实现、最小生成树完整实现、插值查找实现细节、复杂图论题——这些现在不是我的重点。

一句话：**把时间花在数组、哈希、栈、队列、树、递归、DFS/BFS、DP 基础、回溯基础上。**

## 三、各模块的学习思路

### 前置知识（02）

这章要打基础，但不能拖。我打算花 **2～3 天**，重点掌握复杂度概念、递归三要素、栈/队列/链表/树/图的基本概念，能看出一段代码的复杂度。

不打算死背概念，每学一个复杂度就写一个 JS/TS 小例子：

```ts
// O(n)
for (const item of list) {
  console.log(item)
}

// O(n²)
for (const a of list) {
  for (const b of list) {
    console.log(a, b)
  }
}
```

### 数组、查找、排序（03）

这是我第一阶段的核心，计划 **5～7 天**。

重点学：数组结构、二分查找、归并排序、快速排序。
快速过：冒泡、选择、插入、希尔排序。

关键要搞清楚的几个问题：
- 数组增删改查的复杂度
- 二分查找的边界处理（左边界、右边界）
- 快排和归并的思想
- 为什么 JS `sort` 不能无脑用
- 什么情况下要先排序再处理问题

前端场景很多：大列表排序、表格排序、搜索结果排序、接口数据去重、前端分页、数据归并。

我打算做一个**前端表格数据排序 + 二分搜索 Demo**——输入用户列表，按年龄排序，查找年龄大于等于某个值的第一个用户。比单纯写二分更贴近业务。

### 链表（03）

计划 **3～4 天**，掌握高频题就行。

重点：单链表增删查、反转链表、快慢指针、环形链表判断、合并有序链表。双链表和循环链表理解思想即可。

链表在前端业务中不算高频，但思想有价值——LRU 缓存、编辑器 undo/redo、浏览历史、任务链路。

我准备做一个**浏览历史记录管理器**，支持 visit(url)、back()、forward()、current()，用双向链表思想实现。

### 栈、队列、双端队列（03）

计划 **4～5 天**，这部分对高级前端很有用。

栈和队列的典型应用：括号匹配、路径解析、表达式处理、BFS、任务调度。

前端场景更丰富：路由跳转历史、面包屑路径、撤销/重做、弹窗栈管理、请求队列、并发任务控制、BFS 遍历菜单树、理解微任务/宏任务。

我打算做一个**前端请求并发控制队列**——最多同时执行 3 个请求，多余任务进入队列，一个完成后自动执行下一个。这个 Demo 对高级前端简历非常有表达力。

### 集合、字典（04）

计划 **2～3 天**，不难但非常实用。

核心：Set 去重、Map 映射、计数统计、分组聚合、缓存、key-value 查询优化。

前端高频场景：列表去重、权限码匹配、表格分组、选中状态管理、缓存接口数据、ID 到节点映射、路由 path 到配置映射。

我打算做一个**订单列表分组统计工具**——输入订单列表，输出按用户分组、按状态统计、总金额、每组数量。

### 二叉树（04）

这是我整门课最重视的部分，计划 **7～10 天**。

核心中的核心：前序/中序/后序/层序遍历、DFS、BFS、树搜索、树比较、树还原、diff 思想。

前端场景非常多：DOM 树、组件树、路由树、菜单树、权限树、AST、低代码 schema、JSON Schema 表单、虚拟 DOM diff。

学的时候不能只把它当"二叉树题"，要主动迁移到任意树结构的遍历、过滤、查找、扁平化、路径生成、节点比较。

我打算做一个**权限菜单树过滤 + 面包屑生成 Demo**——输入菜单树、用户权限列表、当前 path，输出用户可见菜单、当前页面 breadcrumb、path 到节点的 Map。这个 Demo 非常适合高级前端。

### 二叉搜索树、平衡二叉树（04）

计划 **3～4 天**，不要陷进去。

二叉搜索树要理解左小右大、查找复杂度、插入删除逻辑、为什么退化为链表。平衡二叉树只需要知道为什么需要平衡、旋转是为了降低树高、查询效率从 O(n) 回到 O(logn)。不打算手写 AVL 单旋双旋。

### 堆与堆排序（04）

计划 **3～4 天**，掌握 Top K 即可。

重点：大顶堆、小顶堆、Top K、优先队列。

前端场景：Top K 数据展示、优先级任务调度、性能监控指标排序。

我打算做一个**性能指标 Top K 面板**——输入页面性能数据（页面名称、首屏时间、接口耗时、错误数），输出最慢的 Top 5 页面。

### 哈夫曼树（04）

**0.5～1 天**，看完知道它是什么就行——解决编码压缩问题，高频字符用短编码，是一种贪心思想。

### 图（04）

计划 **5～6 天**，重点是 DFS / BFS / visited / LRU。

图在高级前端里不是每天写，但在复杂系统里很有价值：依赖分析、模块依赖图、表单字段联动、工作流节点、低代码引擎、构建工具依赖图。

我打算做一个**表单字段依赖分析 Demo**——输入字段依赖关系，某个字段变化时找出所有受影响字段，用 BFS/DFS 输出更新链路。这个很贴近中后台和低代码场景。

```ts
const deps = {
  province: ['city'],
  city: ['district'],
  productType: ['productModel'],
}
```

### 动态规划（05）

计划 **6～8 天**，不能完全不会，但也不要无限刷。

重点：青蛙跳台阶、不同路径、打家劫舍、凑零钱、01 背包。

DP 在前端业务中不常直接出现，但思想有用——缓存中间结果、避免重复计算、最优路径、编辑距离、Diff 优化理解。

我打算做一个**多步骤表单最优路径推荐 Demo**，把 DP 思想迁移到业务。

### 回溯算法（05）

计划 **4～5 天**，够用即可。

重点：路径 + 选择列表 + 终止条件 + 撤销选择 + 剪枝。

```ts
function backtrack(path, choices) {
  if (满足结束条件) {
    result.push([...path])
    return
  }

  for (const choice of choices) {
    path.push(choice)
    backtrack(path, choices)
    path.pop()
  }
}
```

前端可以迁移到组合配置生成、动态表单组合、筛选条件组合。我打算做一个**筛选条件组合生成器**。

### 贪心算法（05）

计划 **2～3 天**，不要学太深。

重点：柠檬水找零、跳跃游戏。能识别常见贪心题、能写出高频题就行。

## 五、总周期与节奏

如果每天能学 **1.5～2 小时**，我的计划是：

| 周期 | 内容 | 目标 |
|------|------|------|
| 第 1 周 | 前置知识 + 数组 + 二分 | 建立复杂度和查找基础 |
| 第 2 周 | 排序 + Set/Map + 链表 | 建立数据处理能力 |
| 第 3 周 | 栈 + 队列 + 双端队列 | 掌握任务调度和线性结构 |
| 第 4～5 周 | 二叉树 + BST + diff | 强化前端树结构能力 |
| 第 6 周 | 堆 + 图 + LRU | 掌握 Top K、依赖、缓存 |
| 第 7～8 周 | DP + 回溯 + 贪心 | 面试兜底 |
| 第 9 周 | 复盘 + 高频题 + Demo 整理 | 转化成简历和面试表达 |

总周期 **8～9 周**，不打算压缩到两三周——那样只能变成看课，无法形成能力。

### 每周学习节奏

每周 5 天，每天的时间分配：

| 比例 | 做什么 |
|------|--------|
| 30% | 看课程 |
| 40% | 手写代码 |
| 20% | 刷高频题 |
| 10% | 写复盘卡片 |

算法必须写，光看没有用。

### 每个模块的完成标准

不是"视频看完"，而是满足 5 个标准：

1. 能解释这个结构解决什么问题
2. 能手写核心实现
3. 能说复杂度
4. 能做 2～5 道高频题
5. 能关联一个前端业务场景

比如学完树，我给自己的标准不是只会前中后序遍历，而是要能说出：我可以用 DFS 处理菜单树权限过滤，用 BFS 做层级搜索，用 Map 建立 path 到节点的索引，用递归生成 breadcrumb——这些能力可以迁移到路由、低代码 schema 和组件树处理。

## 八、技术卡片模板

每学完一个模块，我用这个模板沉淀：

```markdown
# 算法模块：树遍历

## 1. 这项能力解决什么问题？
解决层级结构中的查找、过滤、转换、路径生成和比较问题。

## 2. 核心概念是什么？
DFS、BFS、递归、队列、路径维护、节点状态。

## 3. 它在前端岗位中常见吗？
非常常见。菜单树、路由树、权限树、组件树、AST、Schema 都是树结构。

## 4. 典型应用场景有哪些？
- 权限菜单过滤
- 路由扁平化
- 面包屑生成
- JSON Schema 表单渲染
- AST 转换
- 组件树分析

## 5. 常见实现难点是什么？
- 如何保留父级路径
- 如何过滤子节点
- 如何避免递归过深
- 如何构建节点索引
- 如何处理节点 diff

## 6. 面试可能会怎么问？
- 二叉树前中后序遍历
- 层序遍历
- 判断两棵树是否相同
- 翻转二叉树
- 路径总和
- 菜单树过滤实现

## 7. 我需要掌握到什么程度？
能写 DFS/BFS，能处理普通树，能完成菜单、路由、权限相关场景。

## 8. 如果未来项目需要，如何快速恢复？
复习 DFS/BFS 模板，再重写菜单过滤和面包屑生成。

## 9. 可以做的最小 Demo 是什么？
权限菜单树过滤 + path 到 breadcrumb 映射。

## 10. 能否和主线能力结合？
可以。路由系统、权限系统、低代码、组件库、Schema 表单都能结合。
```

## 九、哪些值得后续深入？

**值得深入的：** 树结构处理、DFS/BFS、Map/Set 数据建模、LRU 缓存、请求队列与任务调度、复杂度分析、Diff 思想、依赖图分析。这些能直接进入项目能力和面试表达。

**不值得现在深入的：** AVL 旋转细节、哈夫曼树完整实现、最小生成树、插值查找、希尔排序、双向循环链表、高阶 DP、竞赛图论。不是没价值，而是对我的目标岗位来说投入产出比不高。

## 总结

我的学习主线是：**复杂度意识 → 数组/哈希数据处理 → 栈队列任务模型 → 树结构处理 → 图依赖分析 → 缓存与调度 → 面试高频算法兜底。**

做过动画需求的人都知道：方案太多，选型容易踩坑。CSS 能搞定的偏要上 Canvas，Lottie 够用的非要接 WebGL——不是做不出来，是没选对路。

这篇文章把前端动画相关的技术从底层到上层拆成四个维度，最后给一份实用的选型决策参考。

## 浏览器渲染方式：一切动画的底座

不管你用什么方案，最终都要落到浏览器的渲染能力上。理解这一层，才能理解为什么不同方案性能差异这么大。

| 渲染方式 | 原理 | 典型场景 |
|---------|------|---------|
| **Image/Video 媒体解码** | 浏览器解码图片/视频流，逐帧显示 | GIF、APNG、WebP 动图、视频播放 |
| **DOM/CSS 布局绘制合成** | 解析 DOM 树 → 布局 → 绘制 → 合成层 | CSS transition/animation、DOM 操作动画 |
| **SVG 矢量节点渲染** | 解析 SVG 节点树，矢量路径光栅化 | SVG 路径动画、描边动画、矢量图标动画 |
| **Canvas 2D 位图绘制** | JS 调用 Canvas API 逐帧绘制位图 | 图表动画、小游戏、复杂 2D 动效 |
| **WebGL/WebGPU GPU 渲染** | 着色器直接驱动 GPU 渲染 | 3D 场景、大规模粒子、高性能 2D |

关键认知：**CSS 动画走合成层，性能最好；Canvas 每帧重绘，适合大量对象；WebGL 直驱 GPU，是性能天花板也是复杂度天花板。**

## 动画资源/方案层：你拿到的是什么素材

日常开发中，动画需求通常以"资源"的形式出现。不同资源背后对应不同的渲染路径。

- **Spine** — 骨骼动画，角色/怪物/宠物等带骨骼的 2D 角色
- **Lottie** — AE 导出的矢量动画，UI 动效、图标动画、运营活动动效
- **SVGA** — 分层位图动画，礼物动效、弹幕装饰等
- **GIF / APNG / WebP** — 位图序列，简单循环动图
- **视频** — 复杂成片，开场动画、转场、CG
- **序列帧** — 逐帧位图，老派但可靠的方案
- **SVG 动画** — 矢量路径动画，logo 描边、图形变形
- **DOM/CSS 动画** — 纯代码驱动的结构化动画

## 动画数据驱动层：Spine / Lottie / SVGA 的本质

Spine、Lottie、SVGA 表面上是三种不同的动画方案，但它们的架构模式是一样的：

```
动画描述数据 + 素材资源 + Runtime 播放器 = 可播放的动画
```

区别在于它们**描述动画的方式**不同：

| 方案 | 描述内容 | 素材类型 | 编辑工具 |
|------|---------|---------|---------|
| **Spine** | 骨骼、插槽、网格、纹理图集 | 纹理图集 (.atlas) | Spine Editor |
| **Lottie** | AE 图层、矢量路径、关键帧、图片资源 | JSON 内嵌矢量/图片 | After Effects + Bodymovin |
| **SVGA** | 分层位图、帧状态 | 位图/矢量图 | AE / Sketch 插件 |

选哪个不取决于哪个"更好"，而取决于**设计师用什么工具**和**动画的复杂度**。

- 需要骨骼控制角色？Spine 是唯一选择
- 设计师用 AE 做 UI 动效？Lottie 是最佳搭档
- 需要轻量的分层位图动画？SVGA 够用且文件小

## 工具库/框架层：开发者手里的武器

| 库 | 定位 | 渲染层 | 适用场景 |
|----|------|-------|---------|
| **PixiJS** | 2D 渲染舞台 | Canvas / WebGL | 大量 2D 对象、精灵、粒子 |
| **Three.js** | 3D 渲染场景 | WebGL | 3D 模型展示、3D 场景交互 |
| **lottie-web** | Lottie 播放器 | SVG / Canvas | 播放 AE 导出的 Lottie 动画 |
| **SVGA Player** | SVGA 播放器 | Canvas | 播放 SVGA 格式动画 |
| **Spine Runtime** | Spine 播放器 | Canvas / WebGL | 播放 Spine 骨骼动画 |
| **GSAP / tween.js** | 补间动画引擎 | 通用 | 时间轴控制、复杂补间动画 |

> GSAP 和 tween.js 不绑定渲染方式，它们只负责计算每一帧的数值，渲染由你自己决定。

## 选型决策

把上面的内容压缩成几条决策规则：

| 场景 | 推荐方案 |
|------|---------|
| 最轻量，简单的过渡和状态变化 | **CSS / DOM** |
| 轻量结构化矢量动画 | **SVG / Lottie** |
| 中等复杂度的分层位图动画 | **SVGA / Canvas** |
| 骨骼角色动画 | **Spine / WebGL** |
| 大量对象和粒子系统 | **PixiJS / WebGL** |
| 复杂视觉成片（不适合实时渲染） | **视频 / 序列帧** |
| 3D 场景和模型 | **Three.js / WebGL** |

一句话总结：

> **能用 CSS 就别用 Canvas；能用 Lottie 就别上 WebGL；需要大量对象才上 PixiJS；需要角色骨骼才上 Spine；需要复杂成片就用视频/序列帧；需要 3D 才上 Three.js。**

核心原则就一条：**选复杂度最低、够用的方案。** 每往上一层，开发成本、包体积、调试难度都会成倍增长。先把需求吃透，再决定技术栈。

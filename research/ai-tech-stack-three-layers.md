## AI领域的三层架构

从纵向来分析，我们可以将AI相关知识拆分三层：

```
AI 技术栈
│
├─ AI 应用层 ──── 聚焦：把模型能力落地为用户可用的产品
│   │
│   ├─ AI 产品 ──────────── Chatbot / Copilot / 智能客服 / 知识库
│   ├─ 应用工程 ──────────── RAG / Prompt / Context / Tool Use
│   ├─ Agent 框架 ────────── LangChain / LangGraph / AutoGen
│   ├─ Agent 平台 ────────── Dify / Coze / FastGPT / Flowise
│   ├─ AI 编程工具 ────────── Cursor / Claude Code / Codex / Cline
│   ├─ AI 编程方法论 ──────── 任务拆解 / 上下文组织 / Review
│   ├─ 知识工程 ──────────── Memory / Skill / LLM Wiki / 知识图谱
│   └─ 评估观测 ──────────── LangSmith / LangFuse / Trace / Eval
│
├─ 模型服务层 ──── 聚焦：把裸模型变成可被业务系统调用的服务
│   │
│   ├─ 模型 API / 模型网关
│   ├─ 多模型路由 / 降级 / 限流 / 鉴权
│   ├─ Function Calling / Tool Calling
│   ├─ MCP Server
│   ├─ Embedding / Rerank
│   ├─ 流式输出
│   └─ 日志 / 监控 / 成本控制
│
└─ 裸模型层 ────── 聚焦：模型本体能力与训练
    │
    ├─ 基座模型 ────── GPT / Claude / Qwen / DeepSeek / Llama
    ├─ 训练方法 ────── 预训练 / SFT / RLHF / DPO
    ├─ 微调技术 ────── LoRA / QLoRA / 领域微调
    └─ 核心能力 ────── 推理 / 代码 / 多模态 / 长上下文
```


## 作为前端工程师的聚焦点分析

三层的投入策略可以用一句话概括：

```
应用层：深入 ── 这是主战场
服务层：熟悉 ── 能工程化接入即可
模型层：理解 ── 知道边界在哪就行
```

### 裸模型层：理解原理，判断问题归属

不需要研究模型论文，但要知道模型能力的边界。目标是遇到问题时能快速判断根因：

- 是模型能力不够？
- 是上下文丢失？
- 是检索不准？
- 是 prompt 不清晰？
- 还是真的需要微调？

### 模型服务层：熟悉接口，工程化接入

不需要自己搭模型服务基础设施，但要会用：

- 调用模型 API、处理流式输出
- 设计 Function Calling 的 Tool Schema
- 接入 MCP 工具
- 处理 token 成本、超时重试、多模型 fallback

### AI 应用层：深入投入，这是主战场

这是前端工程师最有优势的一层。因为 AI 应用最终要落到：

```
产品交互    ── 用户怎么和 AI 对话、怎么纠正 AI、怎么确认结果
业务流程    ── AI 输出怎么嵌入原有工作流
状态管理    ── 多轮对话、任务中断恢复、会话上下文
流式 UI     ── 打字机效果、增量渲染、中间状态展示
人机协作    ── 什么时候该人介入、怎么设计确认环节
错误恢复    ── AI 犯错了怎么回滚、怎么重试
权限系统    ── 谁能用什么模型、能看到什么知识
```

这些全是前端工程师日常擅长的领域，只是数据来源从"后端 API"变成了"模型流式输出"。

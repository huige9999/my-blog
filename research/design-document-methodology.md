> AI 时代，高级前端的核心竞争力不再是"能不能写出代码"，而是"能不能把功能设计清楚"。本文提出一套编码前建模方法论：先写设计蓝图，再让 AI 或自己编码。

---

## 一、核心思路转变

传统开发流程：

```
需求来了 → 直接写代码 → 写着写着补逻辑
```

AI 时代应该变成：

```
需求来了 → 先写设计文档 → 明确边界/状态/流程/数据/API/组件 → 再编码
```

**文档不是写完代码后的总结，而是编码前的设计蓝图。**

---

## 二、设计前先回答 6 个问题

不要一上来就选技术栈，先回答：

1. 这个功能解决什么业务问题？
2. 用户会怎么使用它？
3. 页面有哪些状态？
4. 数据从哪里来，到哪里去？
5. 模块之间如何分工？
6. 有哪些异常、边界和风险？

这 6 个问题答清楚，代码基本只是翻译。

---

## 三、设计文档八层结构

### 第 1 层：背景与目标

回答：为什么要做？做完用户能完成什么？不做有什么问题？

防止一上来就陷入技术实现。

### 第 2 层：业务范围

回答：包含什么？不包含什么？边界在哪？

**不定边界，后面 AI 也容易乱写。**

### 第 3 层：用户操作流程

回答：用户从进入页面到完成操作，中间发生了什么？

先写自然语言，再画流程图。覆盖初始化、新增、编辑、删除等各条主流程。

### 第 4 层：核心状态设计

回答：页面有哪些状态？状态在哪初始化？如何变化？何时重置？

| 维度     | 要明确的内容             |
| -------- | ------------------------ |
| 状态名   | 有哪些状态变量           |
| 类型     | 每个状态的数据类型       |
| 初始化   | 初始值是什么             |
| 更新时机 | 什么时候改变             |
| 重置时机 | 什么时候清空             |

**前端复杂度很多时候不是来自 UI，而是来自状态。**

### 第 5 层：数据结构设计

回答三类数据的形状：

- **后端返回结构**（DTO）
- **前端内部使用结构**（如树节点）
- **提交给后端的结构**（Form / Payload）

用 TypeScript interface 定义清楚，AI 生成代码的稳定性会高很多。

### 第 6 层：模块分层设计

回答：哪些逻辑放页面？哪些放组件？哪些放 API 层？哪些放工具函数？

关键不是会写组件，而是知道**逻辑该放哪里**：

- 页面层：组织布局、管理状态、串联流程
- 组件层：展示 UI、管理局部交互、向父组件通信
- API 层：接口请求封装
- 工具层：纯函数、数据处理

### 第 7 层：关键流程伪代码

核心逻辑不用写完整代码，先用伪代码把控制流表达清楚：

```ts
async function submitForm(form) {
  if (form.id) {
    await updateCategory(form)
  } else {
    await addCategory(form)
  }
  dialogVisible.value = false
  resetForm()
  await fetchList()
}
```

伪代码是设计文档和正式代码之间的桥。

### 第 8 层：边界、异常与风险

覆盖以下场景：

- 接口失败时的表现（是否保留用户输入、是否关闭弹窗）
- 表单脏数据（弹窗关闭时是否 reset）
- 数据异常（循环引用、重复 ID、找不到父节点）
- 魔法数字（用枚举替代硬编码状态值）

**实习生只写正常流程，高级前端会提前想异常和边界。**

---

## 四、设计文档公式

```
业务目标 + 功能边界 + 用户流程 + 状态设计
+ 数据结构 + 模块分层 + 关键伪代码 + 异常边界
= 可交付给人/AI 实现的功能设计文档
```

---

## 五、什么时候可以开始编码？

当以下 6 点都明确了，就可以开始：

1. 知道功能包含哪些操作
2. 知道每个操作的主流程
3. 知道有哪些核心状态
4. 知道接口输入输出大概是什么
5. 知道组件/模块怎么拆
6. 知道主要异常怎么处理

不要等文档 100% 完美。推荐的节奏：

```
写 60% 设计文档 → AI 生成第一版代码 → 跑起来 → 发现遗漏 → 补文档 → 改代码
```

---

## 六、如何用 AI 辅助设计

写完设计草稿后，可以让 AI 审查，重点关注：

- 业务流程是否完整？
- 状态设计是否有遗漏？
- 数据结构是否合理？
- 组件拆分是否过度或不足？
- 有哪些异常和边界没考虑？
- 哪些地方需要先和后端/产品确认？

---

## 总结

> 以前高级前端靠代码表达设计；现在高级前端要先用文档表达设计，再让代码实现设计。

编码前建模要练的不是"写文档的文采"，而是背后的**设计能力**：需求不清时能拆清楚，业务复杂时能建模型，状态混乱时能理顺，模块变大时能分层，AI 生成代码前能给出明确约束，生成后能审出问题。

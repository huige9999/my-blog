## 决策chekList

1. **是否有复杂的物理计算（弹簧、重力）或需要随时暂停/倒放？**
    👉 **是：** 用 **JS 补间动画库** (Tween, GSAP, Snabbt)
2. **是否是根据业务数据、时间轴分阶段发生的宏观流程？**
    👉 **是：** 用 **状态控制** (`v-if/show`, `class` 切换)
3. **是否只是单纯的 UI 视觉变化、无限循环、或者简单的 A 到 B？**
    👉 **是：** 用 **纯 CSS 动画** (`transition`, `keyframes`)


## CSS 动画 (Transitions / Keyframes)

定位：性能好
适用场景：
- **无限循环：** 呼吸灯、心跳、雷电抖动、Loading 旋转。
- **简单交互：** Hover 变色、按钮放大、抽屉滑出。
缺点：很难精确控制动画中途暂停、反向播放，不具备物理惯性。

>性能好的原因：`transform` 和 `opacity` 能直接丢给 GPU 合成线程，**不占 JS 主线程**。即使页面 JS 卡死，动画依然丝滑。


## 状态控制动画 (Vue/React Data + CSS)

定位：动画全局流程编排
适用场景：
- **分阶段进场：** 比如：0-2s 发生什么，2-4s 发生什么。
- **组件级生命周期：** 弹窗的显隐、列表项的增删（配合 Vue 的 `<transition-group>`）。
缺点：本质上是触发器，本身不产生补间动画，必须配合 CSS 使用。



## JS 补间动画库 (Tween.js / Snabbt / GSAP)

定位：复杂物理计算
适用场景：
- **物理引擎：** 比如带有摩擦力、弹力的阻尼（Spring）动画。
- **复杂时间线同步：** A 运动到 30% 时，B 开始运动，C 同时放大并跟随抛物线轨迹。
- **重度交互控制：** 拖拽时的动态回弹、跟随鼠标的复杂粒子、以及需要随滚动条（Scroll）进度同步的动画。
缺点：每一帧都在 JS 主线程计算操作 DOM，滥用极易导致性能瓶颈和掉帧；代码是命令式的，容易把组件搞得一团乱。


## 决策思路总结

- 主干逻辑用状态控制划分阶段
- 节点的表现用CSS动画 挂载具体的出入场效果和循环特效
- 极少部分需要物理回弹/复杂轨迹的特定元素，才单独拎出来引入JS补间库处理
